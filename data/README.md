# 球队数据维护

每次完成网站更新后，必须同时生成一份可直接发到球队群里的更新通知。通知规则、固定格式和检查步骤见 [`docs/网站更新规则.md`](../docs/网站更新规则.md)；本次通知见 [`docs/updates/2026-10-17-match-photos-and-douyin.md`](../docs/updates/2026-10-17-match-photos-and-douyin.md)。

更新通过校验后默认提交并推送到 `main`，使 GitHub Pages 对外可访问；只有明确要求暂不发布或只本地预览时才跳过推送。官网公告必须按规则文件中的固定格式发布，并附线上 `#notice/公告ID` 链接。

从 2026 年 10 月 16 日开始，`team-records.json` 是球员资料、赛事和个人统计的唯一来源。数据随项目版本保存，适用于目前的静态网站，不需要服务器数据库。

- `players`：永久球员ID、姓名、资料及 `baseline` 历史累计值。号码不是身份标识，可重复或更换；比赛始终引用球员ID。
- `baseline.through`：历史基数截止日（2026-10-15）。原有17名球员累计数据完整保留；新生此前没有已记录数据，以0开始。历史逐场资料不全，不反推每场出场。
- `historicalMatches`：原有赛事档案，只展示，不再次累加个人数据。
- `matches`：截止日之后的逐场记录。每场唯一ID，记录开球时间、赛事ID、比分、出场、进球、助攻、换人、MVP、战报及照片。
- `player-stats.json`：自动生成的个人统计档案，包含每人的历史基数、累计值和逐场贡献。可以检查每次增加的来源，不手工修改。
- `../js/team-data.js`：自动生成，网站读取的显示数据，不手工修改。
- `生康足球队数据源.xlsx`：迁移前的原始历史存档，原文件保留。其球员数字和赛程不再代表最新累计值；新生、经理、通知资料仍保留在原工作表及现有JS中。旧同步入口已阻止覆盖新系统。

## 每场录入

1. 查 `players` 中的固定ID；新球员先添加资料和0基数，不用号码猜身份。
2. 在 `matches` 增加一条比赛。出场名单每人只记一次；替补席未上场者不记出场。`started` 区分首发和替补，`position` 是本场位置，不修改个人惯常位置。
3. 进球只维护 `events`，助攻写在对应进球的 `assistId`；未知助攻填 `null`，不编造。MVP只维护 `mvpId`。
4. 换人事件与出场记录的 `onMinute`、`offMinute` 保持一致。未知下场时间填 `null`，不据此计算出场分钟。全场时长未知时，不默认90分钟。
5. 零封和低失球场只在明确信息时为相应出场记录填写 `cleanSheet: true`、`lowConcedeGame: true`。未填写不会自行推算。
6. 照片放 `assets/photos/`，在该场 `photos` 中填写 `{ "src": "assets/photos/文件名.jpg", "caption": "照片说明" }`。只使用有明确归属的本场照片。
7. 运行 `node tools/build_team_data.mjs`。系统每次从“历史基数＋逐场记录”重新汇总，自动更新两份生成文件。重复运行不会再次加1；修正记录后重新生成即可。
8. 运行 `node --test tests/match-records.test.mjs tests/tactics.test.cjs` 和 `node tools/build_team_data.mjs --check`，本地查看赛事卡片、详情及个人档案。

网站的分享地址为 `#match/比赛ID`；个人档案的逐场链接也指向同一场比赛。
