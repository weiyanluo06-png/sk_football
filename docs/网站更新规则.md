# 网站更新规则

## 硬性要求

每次更新网站内容后，必须同时生成一份“更新通知”，内容要能直接复制到球队群里。通知至少写清楚：

- 本次更新了什么；
- 涉及哪场比赛、哪位队员或哪个栏目；
- 哪些信息仍待补充；
- 图片、视频或外部账号在哪里查看（如果有）。

本次通知保存在 `docs/updates/`。以后每次更新新增一个日期明确的 Markdown 文件，不覆盖旧通知；给负责人回复时也必须附上同样的群通知正文。

每次网站更新完成并通过校验后，必须提交并推送到 `main` 分支，让其他人可以直接访问 GitHub Pages。除非用户明确要求“暂不发布”或“只在本地预览”，不能只停留在本地；推送前仍须检查 `git status` 和差异，不能覆盖不属于本次任务的修改，也不能强制推送。

每次官网公告必须使用以下固定格式，并提供线上可访问链接：

```text
【生康足球队官网公告｜公告标题】
第一段：说明本次发生了什么、涉及哪场比赛或哪个栏目。
第二段：说明已经同步到官网的具体内容。
第三段：说明队员需要注意的事项或仍待补充的信息。
完整公告：
https://weiyanluo06-png.github.io/sk_football/#notice/公告ID
```

格式要求：首行使用全角书名号样式的公告标题；正文使用 2–4 段简明叙述，不用内部文件路径代替公告内容；结尾固定写“完整公告：”并紧跟对应的线上公告地址。公告地址必须能打开对应的 `#notice/公告ID`，不能只提供本地 Markdown 文件。

内部维护规则、Git 提交流程、数据维护说明和给维护者的交接内容默认只写入项目文档，不得自动制作成官网公告或放入公告列表；只有用户明确要求公开时才发布到网站。

## 数据来源

- 球员、赛事和逐场比赛：`data/team-records.json`。
- 自动生成的累计统计：`data/player-stats.json`。
- 网站读取的数据：`js/team-data.js`，只能通过 `node tools/build_team_data.mjs` 生成。
- 球队经理：`js/manager-data.js`；经理资料来自历史工作簿的 `球队经理` 工作表。
- 通知公告：`js/notices-data.js`。目前公告由已核对内容直接维护；新增公告必须有唯一 ID、日期、正文和发布状态。
- 比赛照片：`assets/photos/`，并在对应比赛的 `photos` 中登记路径、说明和摄影者。
- `data/生康足球队数据源.xlsx` 是迁移前历史档案，不得覆盖 `data/team-records.json` 的逐场统计。

## 更新顺序

1. 先确认用户提供的日期、对手、比分、出场、事件、图片归属和公开范围。
2. 修改唯一数据源或对应内容文件，不直接只改页面显示数字。
3. 运行生成脚本和测试：

```powershell
node tools/build_team_data.mjs
node --test tests/match-records.test.mjs tests/tactics.test.cjs
python tests/team-workbook-sync.test.py
node tests/team-memorial-refresh.test.mjs
```

4. 用桌面和手机尺寸检查赛事详情、通知公告、照片裁切和资源加载。
5. 写入 `docs/updates/日期-主题.md`，并在交付回复中附上可直接转发的通知。
6. 检查 `git status` 和差异，只暂存本次任务相关文件；测试通过后提交并推送 `main`，再核对 GitHub Pages 线上链接。

## 不确定信息

没有提供的助攻、进球时间、出场分钟、照片人物或外部链接不得猜测。使用“待补充”，并在比赛详情或更新通知中说明。
