# 新生展示板块设计说明

日期：2026-07-31
项目：生康足球队纪念站
状态：已确认，待编写实施计划

## 1. 目标

在现有招新板块之后新增一个长期存在的“新生展示”板块，用于欢迎和介绍新学期加入球队的新队员。

新生已经属于球队，但在资料完善和正式参赛前：

- 不进入正式球员大名单；
- 不进入沉浸式首发阵容和阵容调换；
- 不参与现役球员数量统计；
- 不显示出场、进球、助攻、MVP、零封和评分；
- 不参与“全队档案”随机球员展示。

这些内部状态不写在页面文案中。前台只呈现欢迎、人物和球队归属感。

## 2. 页面位置与文案

板块固定放在：

1. 招新；
2. 新生展示；
3. 队史。

页面标题建议：

- 英文小标题：`NEW FACES / 2026`
- 主标题：`新赛季，新面孔`
- 说明：`欢迎新学期来到球队的新队员。认识他们，也记住他们加入球队时最初的样子。`

年份不能永久写死。实施时从新人数据中的年级或独立展示年份生成；无法确定时仅显示 `NEW FACES`。

导航栏在“招新”之后增加“新生”入口，并继续使用现有锚点导航与移动端折叠菜单。

## 3. 卡片内容

所有新人卡片拥有相同尺寸、照片比例和信息层级，不设置主卡或重点人物。

每张卡片展示：

- 真实照片；
- 姓名；
- 年级；
- 球衣号码；
- 主位置；
- 可胜任位置；
- 惯用脚；
- 一句话自我介绍；
- 踢球风格标签。

不展示任何未经正式统计的数据。

### 3.1 字段缺失

- 球衣号码为空时不显示号码区域，不写“0号”；
- 可胜任位置为空时只显示主位置；
- 惯用脚为空时不显示；
- 自我介绍为空时使用“新赛季，一起上场。”这一句统一中性文案；
- 踢球风格为空时使用“等待第一次训练记录”，不能猜测球员特点；
- 照片缺失时显示球队盾牌、姓名和“照片待更新”，不能使用网络人物照片代替。

## 4. 视觉设计

板块延续现有校园足球纪念册风格：

- 背景使用纸白或浅灰绿色；
- 主色使用 `#1f7a4d` 和 `#0f3d2a`；
- 正文使用 `#17231d`，辅助文字使用 `#65746b`；
- 卡片边框使用 `#d7eadf`；
- 卡片圆角不超过 `8px`；
- 踢球风格可以使用浅绿色胶囊标签；
- 不使用紫色渐变、霓虹色、光球、通用 SaaS 卡片或虚构体育品牌效果。

真实照片使用统一的 `4:5` 竖版显示区域和 `object-fit: cover`。单独设置人物照片焦点时，只允许调整 `object-position`，不能改变卡片尺寸。

建议尺寸：

- 桌面端卡片宽度：`220–240px`；
- 手机端卡片宽度：视口宽度的约 `70%`；
- 卡片正文区域使用固定最小高度；
- 自我介绍最多显示两行，过长文字省略；
- 所有卡片始终等宽、等高。

## 5. 横向滚动

新人卡片排列为单行，并自动匀速向左循环滚动。

### 5.1 桌面端

- 默认自动向左滚动；
- 鼠标悬停任意卡片时暂停；
- 键盘焦点进入板块时暂停；
- 鼠标移出后从当前位置继续；
- 滚动速度以约 `38px/s` 为基准，根据轨道总宽度计算动画时长，不能因人数变化明显变快；
- 不显示左右箭头，保持连续纪念册式观看。

### 5.2 手机端

- 默认缓慢向左滚动；
- 手指触摸时立即暂停；
- 支持手动左右拖动；
- 结束手势后延迟恢复自动滚动；
- 横向手势不能阻止正常上下滚动；
- 卡片使用滚动吸附，手动滑动后不会停在半张卡片的位置。

### 5.3 无障碍与性能

- 开启 `prefers-reduced-motion: reduce` 时关闭自动滚动，保留手动横滑；
- 用于无缝循环的复制卡片设置 `aria-hidden="true"`；
- 不重复加载相同图片；
- 视口外照片使用懒加载；
- 页面首屏加载完成后再启动新人照片加载；
- 浏览器标签页不可见时暂停动画。

## 6. 永久板块与无数据状态

无论是否已有新生资料，板块都必须存在。

当“新生展示”工作表没有启用记录时：

- 显示三张等宽、等高的虚拟占位卡；
- 照片区域使用球队盾牌或低对比度球衣号码纹理；
- 卡片文字统一为“新生资料待更新”；
- 辅助文字为“新学期见”或“等待新面孔加入”；
- 不出现虚构姓名、虚构位置、虚构照片和虚构评价；
- 三张占位卡保持静止；只有出现真实新生资料后才启动向左滚动；
- 页面标题和板块高度与真实数据状态保持一致，避免上线后布局突然变化。

这里的“虚拟”仅指版式占位，不代表虚构球员。

## 7. 数据来源

在 `data/生康足球队数据源.xlsx` 中新增工作表：

`新生展示`

建议字段：

| 字段 | 必填 | 用途 |
| --- | --- | --- |
| 排序 | 是 | 控制展示顺序 |
| 姓名 | 是 | 新生姓名 |
| 年级 | 是 | 如 `2026级` |
| 号码 | 否 | 暂未分配时留空 |
| 主位置 | 是 | 如 `CM`、`CB` |
| 可胜任位置 | 否 | 多个位置用 `/` 分隔 |
| 惯用脚 | 否 | 左脚、右脚或双足 |
| 踢球风格 | 否 | 简短标签 |
| 自我介绍 | 否 | 一句话，建议不超过 30 个汉字 |
| 照片文件名 | 否 | 如 `lin-mou.webp` |
| 照片焦点 | 否 | 如 `50% 30%` |
| 展示状态 | 是 | `展示` 或 `隐藏` |

## 8. 数据边界与同步

同步工具 `tools/sync_team_workbook.py` 增加新人工作表读取能力，但新人数据不能写入现有 `players` 数组。

建议生成独立文件：

`js/newcomer-data.js`

该文件只导出：

```javascript
window.NEWCOMER_DATA = {
    season: "2026",
    newcomers: []
};
```

页面脚本只读取 `window.NEWCOMER_DATA.newcomers` 渲染新生板块。

必须保证：

- 修改新生不会改变 `TEAM_DATA.players`；
- 正式球员数量保持不变；
- `startingLineup` 不发生变化；
- 战术板候选池不包含新人；
- 球员弹窗和现役统计不读取新人数据；
- 新人数据为空或文件加载失败时自动进入占位状态。

## 9. 新生进入正式大名单的流程

新生正式进入大名单时：

1. 在 Excel 的“球员数据”中新增该球员；
2. 从“新生展示”中删除该行，或把展示状态改为“隐藏”；
3. 运行同步脚本；
4. 在 `js/team-data.js` 中补充照片、个人介绍和队友评价；
5. 按实际需要决定是否加入首发阵容；
6. 检查新生板块中不再出现该球员；
7. 检查正式球员档案中已经出现该球员。

照片文件可以继续复用，无需重复保存。

## 10. 文件改动范围

预计实施会涉及：

- `index.html`：新增导航入口、新生展示区段和脚本引用；
- `css/style.css`：新增板块、卡片、横向滚动、占位状态和响应式样式；
- `js/main.js`：新人卡片渲染、滚动暂停和触摸逻辑；
- `js/newcomer-data.js`：同步生成的新生数据；
- `tools/sync_team_workbook.py`：读取“新生展示”工作表；
- `data/生康足球队数据源.xlsx`：新增“新生展示”工作表；
- `tests/`：补充数据隔离、空状态和页面结构测试；
- `assets/players/`：保存新生真实照片。

不修改现有球员评分公式、比赛数据、阵容数据和影像墙数据。

## 11. 验收标准

### 11.1 数据

- Excel 新增、修改或隐藏新人后，运行同步脚本能更新网页；
- 新生不会进入正式球员数组；
- 新生不会改变球员总数；
- 新生不会出现在战术板和阵容调换中；
- 新生转入正式大名单后不会重复展示。

### 11.2 桌面端

- 所有照片和卡片大小一致；
- 卡片单行向左匀速滚动；
- 循环衔接无明显跳动；
- 鼠标悬停和键盘聚焦能暂停；
- 标题、卡片和相邻板块间距符合现有设计。

### 11.3 手机端

- 卡片不会被压扁或挤出屏幕；
- 可以手动左右滑动；
- 横向滑动不会导致页面突然向下跳；
- 正常上下滚动不被横向区域锁住；
- 新人照片加载不会明显阻塞首页大图；
- 导航菜单中的“新生”锚点有效。

### 11.4 无数据状态

- 板块保持显示；
- 出现三张一致的“新生资料待更新”占位卡；
- 不出现报错、空白区域或破图；
- 不出现任何虚构球员资料。

## 12. 不在本次范围内

- 新生比赛数据统计；
- 新生评分；
- 新生专属弹窗；
- 在线提交新人资料；
- 后端数据库；
- 管理后台；
- 自动人脸裁切；
- 新生投票、点赞或评论。

这些功能只有在出现真实维护需求后再评估。
